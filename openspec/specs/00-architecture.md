# 00 - 整体架构设计

## 概述

Localverse OS 2.0 采用**微内核 + 插件化**架构，分为四层：
1. 硬件抽象层（HAL）- Java JAR
2. 内核层（Kernel）- WASM + Service Worker
3. 服务层（Services）- 12 大系统服务
4. 应用层（Apps）- 70+ 插件

## 运行模式

### 模式 1：完整模式（Full Mode）
- **条件**：JAR 运行中 + WASM 可用
- **能力**：100%
- **架构**：Browser ↔ Local JAR ↔ Sync Server

### 模式 2：轻量模式（Light Mode）
- **条件**：JAR 未运行，WASM 可用
- **能力**：70%
- **架构**：Browser ↔ WASM ↔ IndexedDB

### 模式 3：纯净模式（Pure Mode）
- **条件**：WASM 不可用
- **能力**：40%
- **架构**：Browser ↔ IndexedDB

### 模式 4：移动模式（Mobile Mode）
- **条件**：移动设备
- **能力**：70%
- **架构**：Mobile Browser ↔ Sync Server

## 数据分层

| 层级 | 位置 | 访问速度 | 容量 | 用途 |
|------|------|----------|------|------|
| L1 | 浏览器内存 | 纳秒 | 1-10GB | 当前工作集 |
| L2 | IndexedDB/WASM | 微秒 | 10-100GB | 热数据 |
| L3 | 本地硬盘(JAR) | 毫秒 | 100GB-10TB | 冷数据 |
| L4 | Sync Server | 秒级 | 无限 | 协作数据 |

## 通信协议

### 五级降级
1. **WebSocket**：双向实时，延迟 <100ms
2. **SSE + HTTP**：单向推送 + 上行请求，延迟 <500ms
3. **长轮询**：30秒长连接，延迟 <30s
4. **短轮询**：5秒间隔，延迟 <5s
5. **离线模式**：本地队列，等待恢复

### 消息格式
```json
{
  "id": "msg_uuid",
  "type": "command|event|data|ack",
  "action": "具体动作",
  "payload": {},
  "timestamp": 1709888888,
  "from": "sender_id",
  "to": "receiver_id|all",
  "replyTo": "parent_msg_id",
  "priority": "normal|high|urgent"
}
```

## 安全模型

### 认证
- 设备令牌（首次配置，之后无感）
- JWT 格式，SHA256 签名

### 授权
- 三角色模型：admin / user / guest
- 资源级别权限控制

### 数据保护
- Level 1（公开）：无加密
- Level 2（内部）：传输加密
- Level 3（敏感）：AES-256 存储加密
- Level 4（机密）：主密码 + 硬件绑定
